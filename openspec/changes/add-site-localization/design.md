## Context

动机与用户可见范围见 `proposal.md`，行为契约见 `specs/site-localization/spec.md`。

当前站点使用 Vite 8.3.1 构建两个 HTML 入口；共享交互在 `web/site.js`，页面脚本处理预览、FAQ、下载和发布记录。`flatten-pages` 将嵌套入口压平，发布工作流只上传 `dist/`。国际化需要同时处理 HTML 入口、站内路径和脚本产生的文字。

## Goals / Non-Goals

**Goals:**

- 建立一条开发与构建共用的模板渲染链路，让每种语言在进入 Vite 之前就有真实 HTML 入口。
- 将内容生成、资源打包和路径压平分成独立职责，保持页面结构与交互复用。
- 让翻译、链接和产物错误在构建或开发过程中被明确发现。

**Non-Goals:**

- 引入客户端路由、服务端渲染框架、通用模板语言或完整翻译管理平台。
- 根据浏览器偏好自动跳转，或保存并覆盖 URL 所表达的语言。
- 改造 Release 内容格式、重新制作截图或调整产品下载策略。

## Decisions

### 1. 在 Vite 处理入口之前生成四份真实 HTML

保留 `web/pages/<page>/index.html` 作为两个页面的唯一模板。在 Vite 配置初始化期间调用构建期生成器，完成读取模板、校验文案和写出 HTML 后，再返回包含入口路径的配置。生成器放在构建工具目录，生成 HTML 放在被忽略的 `web/.generated/` 中，不作为手工维护的源码。

| 逻辑页面 | 语言 | 生成入口，相对 `web/` | 发布文件 |
| --- | --- | --- | --- |
| index | zh-CN | `.generated/pages/index/index.html` | `index.html` |
| index | en | `.generated/pages/index.en/index.html` | `index.en.html` |
| changelog | zh-CN | `.generated/pages/changelog/index.html` | `changelog.html` |
| changelog | en | `.generated/pages/changelog.en/index.html` | `changelog.en.html` |

生成文件继续引用原有根绝对 CSS、图片和页面脚本路径，让 Vite 正常处理模块、资源哈希与共享 chunk。四份入口采用 `build.rolldownOptions.input`，不将同一 HTML 文件以两个别名重复登记。

`transformIndexHtml` 适合转换已存在的入口，本身不负责增加入口数量；在 `generateBundle` 中复制已完成的中文 HTML 也会把语言渲染推到资源处理之后。因此本方案选择先生成真实入口，压平阶段不翻译内容。

参考 [Vite 多页面构建](https://vite.dev/guide/build#multi-page-app) 与 [HTML 转换钩子](https://vite.dev/guide/api-plugin#transformindexhtml)。

### 2. 页面、语言和 URL 使用同一份映射

页面名单、支持语言、默认语言及输出文件规则集中在 `vite.config.js`，由它生成入口清单并传给渲染器和压平插件。渲染器、开发路由、站内链接和产物校验使用同一清单，不各自维护文件名规则。

中文首页与更新日志保留既有文件名，英文使用 `.en.html`。更新架构说明，将原来的“目录名等于产物名”明确为“生成入口目录名等于输出文件名去掉 `.html` 后的名称”，业务页面模板仍各维护一份。

`flatten-pages` 继续只做单次 `src` / `href` 改写、未知引用检查与 `this.emitFile` 落名；其页面识别从仅匹配字母扩展为查清单，不仅放宽正则。所有页面引用压成同目录相对路径，原有锚点及被支持的查询部分保留；无效页面名或未知本地引用直接报错。公开 SEO 绝对 URL 和外部 Release 链接不进入站内压平改写。

### 3. 开发与构建复用同一生成器

`pnpm dev` 与 `pnpm build` 保持既有使用方式，入口初始化由 Vite 配置完成；无需分别维护开发时替换 DOM 和构建时替换 HTML 两套行为。

开发插件监听源模板与语言资源，只在有效输入变化时重新生成所需页面，并触发页面刷新。监听逻辑排除 `.generated/`，防止生成结果再次触发生成；语言资源重新从源文件读取，避免旧的模块缓存。开发 URL 依照同一入口清单映射，`/` 仍指向中文首页。

首次生成失败时给出明确错误；后续编辑出错时展示开发错误，修正后可以恢复。正式构建在生成失败时立即终止。生成器只管理清单内的派生文件，不改写手工维护的源码，也不请求 GitHub API。

### 4. 语言资源一次维护，静态与动态文案共同使用

新增 `web/locales/zh-CN.json` 与 `web/locales/en.json`，按共享内容、首页、更新日志及运行时文案分组。使用同一组语义键，构建期检查支持语言的必需键、值类型与参数集合；英文缺失不静默回退中文。

HTML 模板使用受限的文案和路径占位符。语言资源只保存文本，正文和属性插值统一转义；`code`、编号和其他标记结构保留在模板中，不把整段 HTML 放进翻译值，也不全局搜索替换中文句子。模板渲染后检查残留占位符。

生成器把当前页面需要的运行时文案子集写入 HTML 的 `application/json` 数据块。序列化时转义 `<`，避免文本中的结束标签截断数据块。`web/site.js` 提供共享的语言和文案读取入口，以 `<html lang>` 为当前语言，页面脚本复用该入口。

这能使构建期与运行时使用同一文案源，也避免把整站两种语言的长段静态正文再次打进客户端脚本。无需引入第三方 i18n 运行时。

### 5. 语言切换使用页面链接，并渐进保留锚点

每份 HTML 中直接生成指向对应另一种语言页面的 `<a>`，用目标语言自身的名称作为可见文字，辅助技术标签说明切换目标。站内跨页链接按当前语言生成，各语言共用区块 ID。

语言以 URL 为准，不读取 `localStorage` 或浏览器语言来重定向。`site.js` 初始化语言链接时追加当前有效 `location.hash`，并在锚点变化时同步。禁用 JavaScript 时链接仍保持对应逻辑页面；片段的动态保留作为有 JavaScript 时的增强。访问者切换主题后的持久化行为保持原样。

页面结构无需在点击语言链接后被整体重建。刷新、分享和浏览器后退都沿用原生页面导航。

### 6. 动态文案本地化，Release 数据保持原始形态

主题模式说明、主题切换提示、架构识别后的下载标签及更新日志状态都从共享文案入口获取。更新日志根据当前语言创建日期格式化器，而不是固定使用 `zh-CN`。

已有 `sessionStorage` 缓存继续保存原始 Release JSON，缓存键与语言无关；每个语言页面读取后重新渲染，不能缓存已经格式化的日期或状态 HTML。Release 标题、正文和附件名按原文保留，正文继续用 `textContent` 插入。

API 错误、限流、超时、空列表和下载备用链接按现有数据流程处理，只本地化站点产生的文字。截图保持现有资产，仅标签与 `alt` 使用当前语言。

### 7. 正式发布时使用真实公开地址生成语言关联

各页面生成自身和对应另一种语言页面的 `hreflang`，中文使用 `zh-CN`，英文使用 `en`。公开 URL 由构建期 `SITE_URL` 提供，包含站点子路径；导航链接仍使用可压平的页面路径，两者不混用。

现有 GitHub Pages 工作流在构建前运行 `actions/configure-pages`，将其 `base_url` 输出作为 `SITE_URL` 传入构建，并在缺失、格式无效或指向本机地址时终止发布。本地开发和普通本地构建允许不设置该值，此时不输出正式站点的 SEO 语言关联；需要验 SEO 时传入明确的测试站点 URL。不可猜测实际域名或填入示例域名后发布。

国际化首版不新增通用 canonical 规则；尤其不把英文首页归并到中文首页，也不根据未翻译的 Release 正文临时加入跨语言 canonical。

参考 [Google 语言版本说明](https://developers.google.com/search/docs/specialty/international/localized-versions) 与 [configure-pages 的公开地址输出](https://github.com/actions/configure-pages/blob/main/action.yml)。

### 8. 英文布局保持既有控件的几何约束

预览标签显式保持等宽，不依赖中文标签恰好等长。优先使用简短且准确的英文标签，在窄屏允许控件内文本换行，但标签尺寸与滑块计算继续一致。滑块宽度和位置继续由现有 `layoutThumb()` 管理，不增加第二处动态尺寸写入。

语言切换入口放在共享导航的操作区，使用已有样式令牌。验证英文较长导航、移动端菜单和标签的宽度，不通过缩小全站字体解决局部溢出。既有幻灯片、键盘操作、长图平移和减动效逻辑继续复用。

## Risks / Trade-offs

- [生成步骤增加了派生文件] → 不纳入版本控制，启动与构建自动生成；只操作派生清单，缺失产物必须报错。
- [开发监听引起生成循环或旧文案] → 排除生成目录，重新读取源资源，在输出内容变化后刷新。
- [翻译插值破坏标记或数据块] → 语言资源保持纯文本，分别处理 HTML 插值与 JSON 序列化转义。
- [英文页面链接回中文或丢失部署子路径] → 统一入口映射，检查真实构建产物，并在子路径静态预览中验证。
- [英文预览标签变为不同宽度] → 显式等宽与窄屏验证，保持单一滑块尺寸计算入口。
- [英文页面中仍有中文 Release 内容或截图] → 将这些原始内容作为明确边界，验收站点维护的文字与远端内容时分别检查。
- [发布地址缺失导致错误语言关联] → CI 从 Pages 配置取得地址并校验，普通本地构建不伪造正式 SEO 信息。

## Migration Plan

1. 引入语言资源与生成器，迁移两份页面模板及其动态文案。
2. 接入 Vite 的四份入口、开发刷新、统一 URL 映射和严格压平校验，更新架构与开发说明。
3. 调整正式发布时的站点地址注入，校验所有语言关联的最终目标。
4. 验证开发与产物预览中的四个 URL、根目录和子路径部署、无 JavaScript 静态内容、缓存与 API 失败场景、桌面和移动端布局。
5. 沿用原有工作流发布完整 `dist/`；本变更不包含自动执行线上发布。若需回退，重新部署此前的中文版本产物，无数据或后端迁移。
