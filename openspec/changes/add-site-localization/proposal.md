## Why

CleanU 官网当前只提供中文页面，英文访问者无法用自己的语言了解功能、安全边界和下载入口。为首页与更新日志增加可直接访问、分享和刷新恢复的英文版本，并通过构建期生成完整 HTML 保留静态站点的可索引性与基础内容的无 JavaScript 可用性。

## What Changes

- 保留中文 `index.html`、`changelog.html`，新增英文 `index.en.html`、`changelog.en.html`。
- 两页共用中英文语言资源和页面模板，先生成四份真实 HTML 入口，再交给 Vite 多页面构建与现有路径压平流程。
- 为两页增加普通链接形式的语言切换，保持当前逻辑页面与锚点，站内导航沿用当前语言。
- 翻译页面正文、标题、描述、辅助技术文案、图片替代文本，以及主题提示、下载标签和更新日志状态；发布日期使用当前页面语言格式化。
- 生成中英文对应页面的 `hreflang`，对缺失翻译、未替换占位符和无效站内引用实行构建失败校验。
- 保证英文导航与预览标签在桌面和移动端可用，预览标签继续保持等宽。
- 首版复用现有真实中文截图；GitHub Release 标题、正文与附件名称展示远端原文。语言由 URL 确定，不增加自动语言跳转、机器翻译或第三方运行时服务。

## Capabilities

### New Capabilities

- `site-localization`: 首页与更新日志的中英文静态版本、语言切换、语言一致的站内导航、静态与动态文案本地化，以及构建与开发环境的一致性。

### Modified Capabilities

无。当前项目没有已发布的 OpenSpec 能力规格。

## Impact

- `vite.config.js` 中的多页面入口、开发路由、页面 URL 映射与 `flatten-pages` 校验。
- 新增构建期入口生成器与 `web/locales/` 语言资源，调整两页 HTML 模板；生成文件不纳入版本控制。
- `web/site.js`、两页脚本中的动态文案和更新日志日期格式，以及 `web/styles.css` 的语言切换与等宽标签布局。
- 开发、构建命令共用的入口初始化步骤，`.gitignore` 和相关架构、开发说明文档。
- `.github/workflows/publish.yml` 在构建前取得真实 Pages 地址，并将其提供给语言关联的生成过程。
- 继续只部署 `dist/`；现有中文 URL、GitHub Release 数据源及下载逻辑保持兼容，不引入后端或强制新增运行时依赖。
