## Context

动机见 proposal.md，用户可见行为见 site-checkout delta。本变更引入外部支付跳转、敏感查询参数处理和跨仓库上线顺序，满足创建 design 的条件。

站点使用 Astro 生成八个中英文静态页面，HomePage 的购买按钮仍 disabled。locale JSON 展示三台设备，隐私政策只描述手动更新联网，支持页只提供公开 Issues。SiteLayout 共用元信息与语言导航，所有部署使用现有 Publish 完整流水线，下载与 appcast 来自已发布 App。

app-licensing 的行为由相邻 clean-mac 仓库同名 change 定义。该方案不依赖官网服务器验证订单或签发授权；App 持 key 与实例向 Dodo 验证。

## Goals / Non-Goals

**Goals:**

- 保持静态页面、普通导航、locale 唯一文案源与部署子路径兼容。
- 支付页可暂时不可用而不影响已有许可证校验；付款前清楚了解产品规则，付款后有可操作的邮件激活与支持步骤。
- 回跳页只处理最少的提示状态，不让订单参数成为授权凭据或传播到其他页面。

**Non-Goals:**

- 不增加 Next.js/API 路由、Cloudflare Worker、账号或数据库，不集成需商户密钥的 Checkout Sessions 和设备管理。
- 不把浏览器成功状态当作独立查单结果，不为此新增客户端订单轮询或自建 Webhook。
- 第一版不使用自定义 URL scheme 自动激活，用户从 Dodo 邮件复制许可证到 App。

## Decisions

### 1. 配置驱动的静态 Payment Link

增加一个小型构建期购买配置模块，供页面与现有构建校验共同使用，不新建通用支付平台封装。公开配置包括环境、商品/商户标识、Dodo 原始 Payment Link、购买开放开关及支持授权的最低 App 版本。购买支持邮箱只在 Dodo 后台设置，不进入网站、App 或仓库；浏览器不接触商户 API key。

正式链接采用官方 https://checkout.dodopayments.com/buy/{product_id} 契约，固定 quantity=1，使用 URL API 生成 redirect_url。2026-10-20 从 Dodo API 取得真实测试 Payment Link，核对测试主机为 https://test.checkout.dodopayments.com。链接生成按环境匹配固定主机，并核对商品、路径、站点 origin 与子路径，拒绝用户名密码、任意跳转目的地和占位配置。

PURCHASE_ENABLED 默认关闭。关闭时允许发布现有下载站点，显示本地化的未开放状态；开启时任何必需配置缺失即构建失败。最低版本检查只防止错配旧版下载，不能替代真实激活验收。沿用 $9 显示，不在浏览器维护另一份实际收费金额；税费与结算币种以 Dodo 结账展示为准，上线前核对含税/未税措辞。

实现以 src/data/purchase-config.json 保存已核对的真实测试标识与 Payment Link，src/data/purchase.js 校验并接受非空环境变量覆盖。正式公开开关仅允许 live，测试链接生成能力仅用于独立测试，不能以 test 环境开放公开购买。PURCHASE_ACCEPTANCE_REFERENCE 要求维护者提供实际验收记录位置，其中需确认 Dodo 后台支持入口已配置；构建不读取邮箱。字符串与版本校验不能证明记录内容或真实链路已通过。脚本测试的 fixture 与实际测试资源分别维护，不写入假生产值。

开发验收使用受信任管理 MCP 创建一次性测试 Checkout Session，接收维护者授权测试邮件的地址，并回到本机预览页；这不进入网站产物或运行时架构。测试订单已成功，自动许可证权益和两封邮件交付状态已核对。Dodo 默认品牌支持邮箱的 API 更新返回 403，需通过商户后台手动配置。网站仅指引用户使用 Dodo 购买邮件中的支持入口。

App 的“购买”入口打开当前语言官网定价区，从而共用条款和维护状态。官网购买关闭不改变已售许可证的有效性，也不成为 App 校验依赖。

### 2. 新增两类共用页面，保持 Astro 结构

| 页面标识 | 中文路径 | 英文路径 | 组件 |
| --- | --- | --- | --- |
| checkout | /purchase/complete/ | /en/purchase/complete/ | CheckoutPage |
| terms | /purchase-terms/ | /en/purchase-terms/ | PurchaseTermsPage |

在 src/i18n/routes.js 注册页面标识，为每种语言创建薄 Astro 入口，正文、样式与脚本放在各自组件目录。locale JSON 新增 checkout 与 terms 文案，SiteLayout 根据页面属性提供标题、描述、语言配对与回跳专用元信息。新增四个页面后预期共十二个页面，不删除既有八页，也不继续用固定八页的断言漏检新页面。

新增条款入口放在定价区、支持页和购买完成页。主题、键盘导航、减动效及窄屏规则复用现有实现；付款状态变化通过可访问状态区域提示，不引入前端框架。

add-site-localization 尚有独立的上线验收任务，保持原记录。本 change 覆盖新增页面，不把新增支付工作或完成声明写回该未归档变更。

### 3. 回跳页提供状态提示，不验证订单

静态 HTML 默认展示“查看邮件并在 App 中激活”的中立说明。页面脚本只读取 status，将白名单 succeeded、processing、failed、cancelled 映射到预定义文案，其他值统一未知。支付已处理状态仍标为支付服务返回的提示，不声称本站已查单；刷新丢失参数后仍可按邮件完成激活。

Dodo 邮件是默认交付渠道。页面不展示 URL 中的 email、payment_id 或 license_key，也不在网页执行激活。处理中或未知状态不引导立即重复付款；失败或取消时提供返回定价入口，已扣款但未收到许可证则先联系支持。无脚本时保留完整静态邮件步骤、条款和支持链接。

### 4. 尽早丢弃查询参数，限制继续传播

Dodo 会把支付信息追加到 redirect_url。回跳页使用尽早执行的内联初始化，仅将白名单状态映射为内存中的枚举，然后通过 history.replaceState 移除全部查询参数与不需要的片段，不保存原始 URL。后续组件脚本只接收枚举，不接触订单或许可证字符串。

回跳页配置 noindex 和 no-referrer，在 HTML 头及 Cloudflare 静态响应头中限制传播；回跳专用响应头覆盖中文、英文和部署子路径，不使用动态服务。回跳页不载入第三方分析、图片或脚本，不将状态及其他参数放入 localStorage、异常上报或复制链接。

语言切换和站内链接由路由辅助生成，仅保留逻辑路径，不保留购买查询。DOM 只使用 locale 资源中的预定义文案，不把参数插入 HTML。HTML 无脚本或初始化失败时仍有 no-referrer 与中立指引；地址清理不宣称可以删除 Cloudflare/Dodo 已接收的初始请求日志。

### 5. 条款、隐私与私密支持同步修改

产品规则只维护一套中英文语义。首页保留 30 天完整试用、永久更新和两台使用名额，移除离线验证条目，设备说明使用普通用户语言；购买条款集中说明首次联网、定期验证和最长七天离线的使用条件，不展开 24 小时后台调度等实现细节。支持与 Dodo 邮件遵循相同授权规则。

条款采用“不提供无理由退款；适用法律及支付平台要求的例外另行处理”的产品政策，不写绝对无退款承诺。重复扣款、未交付、名额异常和旧设备丢失通过 Dodo 购买邮件中的支持入口处理；不要求把完整 key 发到公开 Issues。App 按维护者要求移除联系支持、复制编号与“更多”入口，官网不保存支持邮箱或生成邮件链接，只提示用户通过 Dodo 订单邮件提供购买邮箱、必要订单信息与问题描述。购买支持仅请求识别订单所需信息，不索要银行卡完整资料、文件扫描结果或电脑序列号。

隐私页增加 Dodo 支付与授权服务角色，明确授权请求携带许可证、实例 ID 和随机安装名称，订单邮箱及付款信息由 Dodo 结账处理，并说明本机 Keychain 记录及定期联网校验，保留数据处理披露，移除离线天数和具体校验频率。更新请求仍为用户主动触发，但不能继续笼统宣称整个 App 只在用户检查更新时联网。保留不上传本地文件与清理历史的准确描述，修正“删除 Application Support 即删除所有应用记录”的过度说明，并同步页面更新时间。

源码 PolyForm Noncommercial 条款与官方二进制收费说明需由维护者在正式购买前核对，本 change 不直接更换源码 LICENSE。Dodo 后台的支持入口、商户信息、税费及最终条款内容是上线配置输入，不把支持邮箱复制到站点配置或代码。

### 6. 生产开放沿用现有 Publish

公开配置仅增加到现有构建验证与 Publish 输入。继续执行发布同步、测试、Astro 构建、DMG 恢复、appcast 校验和 Pages 部署；支付页面不启用另一个 Cloudflare 自动构建或精简发布入口。

构建在 PURCHASE_ENABLED=true 时检查当前下载版本不低于配置的授权兼容版本，并要求维护者已有测试链路验收记录；不能仅修改版本号就声称 App 可激活。应用自动通知与官网手动 Publish 使用相同配置检查，关闭新购买时不移除已售用户需要的说明。

## Risks / Trade-offs

- [浏览器回跳可以被伪造或丢失] 只用于提示，交付依赖 Dodo 自动邮件，使用权限由 App 激活校验决定。
- [回跳 URL 可能包含敏感信息] 不展示或持久化、尽早清理、限制 referrer 与索引；如实说明无法消除初始托管日志。
- [收款成功但邮件延迟] 保留中立领取与私密支持步骤，避免提示重复付款；真实发码流程必须在测试环境验收。
- [静态配置和商品不一致] 正式构建失败门禁与商户检查表一起使用，测试环境值不进入正式开启状态。
- [自助远程换机能力有限] 明确只能本机释放，其他实例通过维护者可信管理环境处理，不把商户密钥放到网页。
- [官网与 App 规则漂移] 同名 change 对照同一验收表；开放购买前逐项核对，不把新文案当作已有实现。

## Migration Plan

1. 先实现页面、公开配置校验和关闭购买状态；用示例配置验证静态构建，但不把示例当生产商品。
2. 与 App 使用同一 Dodo 测试商品，核对自动邮件、数量与实例上限，测试回跳未知/成功/处理中/失败/取消及敏感查询参数处理。
3. 发布并下载支持授权的 App，验收完整试用、两设备激活、第三实例拒绝、取消与异常恢复、七天期限及明确失效。
4. 维护者在 Dodo 后台配置支持邮箱，并补齐正式商户/商品/Payment Link、公开站点地址、兼容版本、税费与条款，记录后台设置验收，执行完整 Publish 后开放新购买。
5. 发生支付问题时通过同一流程关闭购买，保留条款与支持页，不撤销已售许可证或回滚到不支持激活的旧 App。
